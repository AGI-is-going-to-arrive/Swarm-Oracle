Design Lens

按 teach-impeccable 对齐后的页面视角

这页不是普通实验报告，而是给策略型用户快速读懂 detector 行为的浏览器控制台。设计上下文来自项目现有的 .impeccable.md：用户是浏览器里的策略型探索者，品牌气质是 cinematic / tactical / legible。

为什么它长这样

页面保留了“可玩的指挥室”气质，但刻意避免做成发光赛博面板或装饰性 AI 海报。顶部是命令条，正文是实验地图、交互沙盘和证据区块，目标是让第一次打开的人在几十秒内就能回答三个问题： 哪个变量最强、为什么会 fork、怎样压住 branch 爆炸。

01
战略可读性优先 先给结论，再给交互，再给证据；避免读者被实验细节淹没。
02

Variable Map

这一轮到底控制了什么

页面里的变量分成两类：真正被拿来做实验的旋钮，以及系统先天存在、必须同时满足的硬门槛。

实验旋钮

temperature

影响模型在既定 detector rubric 下如何解释同一批 diverge 信号。它会改 fork 命中率，但不是单调线性旋钮。

  • 在保守 detector 下，会改变“这是互斥未来还是同一路线细节争论”的判断。
  • 在激进 detector 下，更像调节 fork 强度，而不是命中率开关。
实验旋钮

branch_sensitivity

直接进入 detector prompt 的灵敏度值。它确实有影响，但这题上不是“越高越容易 fork”的简单开关。

  • 更像是 detector 的边界提示量，而不是硬阈值。
  • 和 prompt、temperature 强耦合，单独读它容易误判。
实验旋钮

fork_prompt_variant

决定 detector 认为什么叫“足够 fork”。这是本轮最强的影响项。

  • A：基线保守。
  • B：把互斥未来、制度分流、积极先验一起叠满。
  • C / D：分别测“互斥未来即足够”和“制度分流即足够”。
结构开关

k / detector budget

fork_detector_active_branch_limit。不是限制谁说话，而是限制每轮还有多少条 active branch 能继续跑 detector。

  • k=0：默认行为，所有 active branch 都可继续分叉。
  • k=1：只保留最高优先级那一条继续分叉，跨题都能压住爆炸。
上下文变量

rounds

不是 detector 的显式评分项，但它会改变可分叉窗口数量，也会改变同一 prompt 的行为模式。

  • 轮数越长，越容易进入 branch fan-out 和长尾 narration。
  • 对照实验必须固定 rounds，否则会把 prompt/temperature 效应掺脏。
系统硬门槛

必须先满足的条件

这些不是本轮旋钮，而是 fork 前置条件。

  • diverge_signals 非空
  • 不是最后一轮
  • 当前 active branch 数未到系统上限

    Takeaways

    读完这页后该记住什么

    Prompt 是主导项

    同一题、同一温度、同一 sensitivity，仅仅更换 detector prompt，就能把 fork 命中率从 0 拉到 1。

    结构预算比提示词压缩有效

    k=1 跨题都能明显压低 branch 数；而“在 prompt 里要求少分几条”并没有成功抑爆炸。

    C 与 D 是强因子

    C 把“互斥未来”视为充分条件；D 把“制度/审批/责任链分流”视为充分条件。它们都不是题目特异幻觉。

    页面依据本轮真实产物整理，包括 `musk-factor-matrix`、`musk-sensitivity-temperature-matrix`、 `musk-prompt-ab-matrix`、`musk-prompt-ablation-matrix-r3`、 `budget-generalization-matrix` 与其它对照实验。结论用于解释 fork 行为，不直接等价于产品默认配置建议。
