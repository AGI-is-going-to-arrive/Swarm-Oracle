# 本地开发与验证 / Local Development and Validation

命令以仓库根目录为起点。Python 应用使用 `backend/.venv`，前端使用 npm 与 `frontend/package-lock.json`。Python/uv 约束以 `backend/pyproject.toml` 为准，Node 兼容范围与 npm 版本以 `frontend/package.json` 为准。本地默认 backend `127.0.0.1:18927`，frontend `127.0.0.1:18928`。

不要把真实 API key 写进命令历史、文档、测试工件或 replay。

Commands start at the repository root. The Python application uses `backend/.venv`; the frontend uses npm and `frontend/package-lock.json`. `backend/pyproject.toml` defines Python and uv constraints, while `frontend/package.json` defines Node compatibility and npm version. Local defaults are backend `127.0.0.1:18927` and frontend `127.0.0.1:18928`. Real API keys never belong in command history, documentation, test artifacts, or replays.

## 初始化 / Initialization

原生环境、CI 和 Docker 消费同一份已提交的 `backend/uv.lock`。使用锁校验的 `uv sync --directory backend --locked --extra dev --no-build`；不能用跳过过期锁检查的选项代替，也不在目标平台临时解析未锁定构建依赖。没有匹配 wheel 时明确失败。

uv 位于独立 tooling environment，与 `backend/.venv` 及用户已有的根 `.venv` 分开。否则同步应用环境可能删除正在运行的工具，尤其会影响 Windows；不能重建用户根环境来避开这个问题。按照中英文 README 的平台命令安装匹配版本，使用 manifest 固定的 npm，不全局替换宿主工具。环境模板只在目标不存在时复制，不能覆盖已有配置。

Native development, CI, and Docker consume the committed `backend/uv.lock`. Synchronization uses `uv sync --directory backend --locked --extra dev --no-build`; options that skip stale-lock checks or resolve unlocked build dependencies on the target platform are not substitutes. Missing matching wheels fail explicitly. uv lives in an isolated tooling environment separate from `backend/.venv` and any user-owned root `.venv`, preventing application sync from deleting the running tool, especially on Windows. Install the matching version with the platform command in the bilingual README and use the npm pinned by the manifest rather than replacing host tools globally. Copy environment templates only when the destination is absent; never overwrite existing configuration.

## 启动 / Startup

终端 1：`cd backend && source .venv/bin/activate && uvicorn --app-dir . app.main:app --host 127.0.0.1 --port 18927`

终端 2：`cd frontend && SWARM_BACKEND_URL=http://127.0.0.1:18927 npm run dev -- --host 127.0.0.1 --port 18928`

仓库根也可 `make preflight`、`make dev-backend`、`make dev-frontend`。`make preflight` 的 `fail` 返回非零；可选能力缺失用 `warn`。LLM 检查会实测精确本地 URL，空/占位 key 不发送 `Authorization`。原生 Makefile/dev 入口默认 loopback；容器进程监听容器接口，Compose 默认仅把服务发布到宿主 loopback。

配置 `SESSION_SECRET` 后业务 API 需要 `X-Session-Token`。

Preview：`cd frontend && npm run build && SWARM_BACKEND_URL=http://127.0.0.1:18927 npm run preview -- --host 127.0.0.1 --port 18930`。dev 和 preview 都代理 `/api` 与 `/ws`。

Docker：Windows/macOS 使用 Docker Desktop 的 Linux 容器模式，Linux 使用 Docker Engine 与 Compose 插件。当前 backend 镜像以 UID 1000 非 root 运行；旧 root 容器创建的命名卷必须按 `deploy/README.md` 的停机、完整 `/data` 备份校验、一次性 `chown` 和写入验证流程升级，新卷无需迁移。frontend 反向代理的 `/api` 请求体上限必须容纳后端 50 MiB Snapshot 合同及 multipart framing，并关闭代理缓冲以保持 SSE 增量可见；各 endpoint 仍由后端执行自身的更窄限制。Compose 把 18927/18928 绑定到 `127.0.0.1`。公开部署前设置 `ENV=production`、唯一 `SESSION_SECRET`、唯一 `ADMIN_TOKEN` 和正确 CORS。完整宿主命令以中英文 README 为准，Makefile 只是 POSIX 终端便捷入口。

Linux 的 host gateway 映射只解决容器名称/地址，不保证宿主仅监听 loopback 的 LLM 接受容器连接。`network_mode: host` 也会改变端口与 frontend DNS，不能把单行切换当作完整修复。镜像晋升、实例备份及旧版本恢复的执行边界见 `development/release-integrity.mdx`。

容器验证只能使用本任务创建且可明确归属的容器、网络和卷；无法创建隔离资源是证据阻断，不能转而复用或改动用户正在运行的服务。

Run the backend with its virtual environment and Uvicorn on loopback, and run the frontend with `SWARM_BACKEND_URL` on port 18928. Root Make targets provide preflight and convenience startup; a failed preflight exits nonzero, optional capability absence is a warning, and LLM checks probe the exact local URL without sending Authorization for an empty or placeholder key. Native entry points default to loopback. Containers listen inside their network while Compose publishes host ports on loopback. With `SESSION_SECRET`, business APIs require `X-Session-Token`. Preview builds first and proxies `/api` and `/ws`. Docker uses Linux containers; the backend image runs as UID 1000. A legacy root-owned volume is upgraded only through stopped service, verified full `/data` backup, one-time ownership repair, and write verification. The frontend proxy must accommodate the backend 50 MiB snapshot contract plus multipart framing and keep SSE unbuffered, while endpoints retain narrower limits. Public deployment sets production environment, unique session and admin secrets, and correct CORS. Linux host-gateway mapping changes reachability but does not make a loopback-only host LLM accept container traffic; host networking also changes ports and frontend DNS. Container validation uses only resources created and labeled for the task. Failure to create isolation blocks evidence rather than authorizing reuse of a user's running service.

## 最小验证 / Minimal Validation

先跑与改动直接相关的测试，再扩大范围。不要顺手修复无关失败。

Backend：`cd backend && source .venv/bin/activate && python -m pytest -q tests/<target_test.py> && ruff check app/ tests/<target_test.py>`

Frontend：`cd frontend && npm test -- --run src/<target_test> && npm run lint && npx tsc -b`。`npx tsc -b` 是类型门禁；`npm run build` 也会先执行它。不要用 `tsc --noEmit` 替代。

样例与资产：`python scripts/validate_samples.py`；`cd frontend && npm run assets:provenance:check`。

官方样例由 catalog 与确定性 generator 产生，必须保留 synthetic provenance，不能声称其中续跑由真实用户或 provider 执行。native 子分支只拥有 fork 后轮次并继承父前缀；replay 则持有自包含前缀，原始消息证据须逐字保留。仅添加 replay metadata 不能修复非法谱系。全分支 resume 不冒充特定角色行动；counterfactual 保留独立 actor 要求。generator 的字节检查和 validator 的语义检查都以正常分支合同为准，不能放宽运行时验证来迎合错误样例。

`backend/pyproject.toml` 中的 Web 框架、表单解析与 metrics 集成采用协调的安全/兼容范围：升级时必须整体检查 router 重载、文件上传与表单、WebSocket/SSE、错误响应和 `/metrics`，不能只验证依赖可解析或单独放宽其中一项。PDF、multipart 与 HTTP 传输安全下界不得无理由回退；精确版本范围以该文件为准，稳定文档不复制版本快照。

真实 provider 测试不进入默认单元测试。确认本地兼容网关时：`RUN_REAL_LLM_TESTS=1 python -m pytest tests/test_llm_gateway_probe.py -v -s`。HTTP 2xx 中的 error envelope、无可见正文或未形成终态的 stream 都是 provider 失败，不能用本地 fallback 代替上游能力结论。

Start with tests directly related to the change and widen only as needed. Backend validation runs focused pytest and Ruff inside `backend/.venv`. Frontend validation runs the focused Vitest target, lint, and `npx tsc -b`; `tsc --noEmit` is not the project-reference gate. Sample and asset checks use their canonical scripts. Official samples come from a catalog and deterministic generator and retain synthetic provenance. Native child branches own only post-fork rounds and inherit the parent prefix; replay carries a self-contained prefix; original message evidence remains verbatim. Metadata cannot repair illegal lineage. All-branch resume does not impersonate a specific actor, while counterfactual actions retain explicit actor requirements. Generator byte checks and validator semantics follow the runtime branch contract. Framework, multipart, metrics, PDF, and HTTP dependency ranges move as a coordinated compatibility and security surface rather than isolated resolver edits. Real-provider tests are excluded from defaults. The opt-in gateway probe treats HTTP 2xx error envelopes, missing visible body text, and streams without a terminal as provider failures; local fallback cannot substitute for upstream capability evidence.

## 发布签收 / Release Signoff

先启动 backend 和 preview，再 `cd frontend && npm run release:signoff -- --url http://127.0.0.1:18930 --headless`。fixture 必须拦截 API、Node backend helper 和同源 WS；未命中 allowlist 的请求应使 suite 失败。`--dry-run` 只记 `planned`，不能作为已执行通过。

release signoff 的 child process 必须保持 argv 边界并使用 `shell:false`；Windows 的 npm/npx 通常通过已安装 npm 的 JavaScript CLI 启动，不能把 Python/Node/Git 参数交给 `cmd.exe` 重解析。只有 Windows 上 npx 的参数含 CR/LF 时，运行时才会为该次调用选用 PATH 中现有 Git for Windows 的 Bash，因为 npm 内部再次经过 `cmd.exe` 会截断换行参数。Git Bash 解析时也会移除原始 CR；含 CR 的调用因此只为该次 Node 进程添加 data URL preload，通过已选 `npx-cli.js` 加载同一 npm 安装内的 `@npmcli/promise-spawn/lib/escape.js`，沿用它的 shell 引用规则并在 Bash 中拼回 CR。该内部入口缺失或不是预期函数时明确失败；只有 LF 的参数不加载 preload。该路径会先用独立、强制离线且关闭更新提示的环境查询 npm `script-shell`；若命令行、环境或 npm 配置已明确覆盖 shell，无法完成配置查询，或找不到 Bash，就拒绝运行并提示改为直接用 Node.js 执行。它不修改 npm 安装文件、`NODE_OPTIONS` 或全局环境；MSYS 路径转换仅在这个 child process 的复制环境中关闭，普通调用、父进程环境和用户全局 npm 配置保持不变。CI 的精确 OS/runtime 矩阵由 workflow 自身负责，不写入稳定知识。

浏览器工件只证明对应 URL、commit、provider 和浏览器组合。不要把旧工件当作当前 HEAD 的签收结果。session 级测试数量、日期、截图目录和修复过程不写入 llmdoc。

Release signoff starts backend and preview, then runs the canonical headless signoff command against port 18930. Its fixture intercepts API, Node backend helpers, and same-origin WebSocket; any non-allowlisted request fails the suite. `--dry-run` records only `planned` and is not execution evidence. Child processes preserve argument boundaries with `shell:false`; on Windows, npm and npx normally launch through the installed npm JavaScript CLI so Python, Node, and Git arguments are not re-parsed by `cmd.exe`. Only an npx invocation with CR/LF in an argument selects an existing Git for Windows Bash from PATH for that child, because npm's nested `cmd.exe` path truncates multiline arguments. Git Bash also removes raw CR while parsing. For arguments containing CR, that invocation alone adds a data URL preload to the Node process, resolves `@npmcli/promise-spawn/lib/escape.js` from the selected `npx-cli.js` installation, retains its shell quoting, and reconstructs CR inside Bash. A missing or incompatible internal entrypoint fails explicitly; LF-only arguments do not load the preload. Before choosing Bash, the runtime queries npm `script-shell` in an isolated environment forced offline with update notices disabled. An explicit shell override from CLI, environment, or npm configuration, a failed configuration query, or missing Bash causes a closed failure with guidance to invoke the program directly with Node.js. This path does not modify npm installation files, `NODE_OPTIONS`, or global environment. MSYS path conversion is disabled only in the copied child environment; ordinary invocations, the parent environment, and global npm configuration remain unchanged. Browser artifacts prove only their URL, commit, provider, and browser combination. Old artifacts do not sign off current HEAD, and session-specific counts, dates, screenshot paths, and repair history do not belong in stable knowledge.
