# 发布镜像与实例恢复 / Release Images and Instance Recovery

此工作流约束候选镜像晋升、实例升级与恢复。精确命令、版本和平台矩阵以 workflow、Dockerfile 与 `deploy/README.md` 为准；本地源码测试、浏览器 preview、最终镜像运行和模型质量是不同证据。

This workflow governs candidate-image promotion, instance upgrades, and recovery. Workflows, Dockerfiles, and `deploy/README.md` remain the source for exact commands, versions, and platform matrices. Local source tests, browser preview, final-image execution, and model quality are different evidence.

## 候选镜像与晋升 / Candidate Images and Promotion

先记录同一源码 revision 的 backend/frontend manifest digest，再让声明的平台实际执行这对镜像。候选验证使用镜像内交付的命令、Nginx 和应用，不以 native Vite preview 替代迁移、非 root 数据写入或容器传输验证。

镜像验收在独立网络与新数据卷中验证样例导入、snapshot 往返、真实 backend WebSocket 心跳、无缓冲报告 SSE、写入、重启和恢复后读取。延迟失败的隔离 provider 只证明流式传输与失败终态；固定 embedding 的 Chroma 读回不依赖模型下载。它们均不证明外部模型质量。

晋升必须等待所需镜像门禁和相同 revision 的发布签收，直接复制已验证的 digest，不能测试后重新解析可能移动的 SHA 标签。backend/frontend 作为一对处理；失败时恢复先前 tag 对，旧 `edge` 候选不能覆盖更晚的 main。若回滚失败，必须显式报错而非宣称发布原子完成。

创建和清理的容器、网络、卷须有本次任务的精确身份与归属标签。不能因为隔离环境不可用就复用现有用户服务；配置了某平台或浏览器也不代表已经观察到该组合通过。

Record backend and frontend manifest digests from one source revision, then run that exact pair on every declared platform. Candidate acceptance uses commands, Nginx, and the application shipped inside the images rather than native Vite preview. It verifies sample import, snapshot round-trip, a real backend WebSocket heartbeat, unbuffered report SSE, writes, restart, and restored reads in an isolated network and fresh volume. A delayed-failure provider proves transport and terminal-failure behavior only; fixed-embedding Chroma readback avoids model download, and neither proves external-model quality. Promotion waits for required image gates and release signoff from the same revision, then copies immutable digests rather than resolving a moving SHA tag. Backend and frontend move as one pair. Failure restores the earlier tag pair, an old edge candidate cannot overwrite newer main, and rollback failure is reported explicitly. Every container, network, and volume has task-specific identity and ownership labels. Missing isolation blocks the evidence; it never authorizes reuse of a user's service. Configuring a platform or browser is not proof that it passed.

## 完整实例备份 / Complete Instance Backup

先停止所有可能写入所选实例数据的进程或容器。备份覆盖配置的数据范围，包括 SQLite 的原始 WAL/SHM 及全部 Chroma 状态；脱敏 Scenario snapshot 不能替代实例备份。POSIX 无法核实打开文件时拒绝继续，Windows 保持排他文件句柄，卷备份拒绝仍被运行容器挂载的来源。

备份时不对原 SQLite 做恢复写入。先复制并核对来源一致性，再在临时恢复副本中检查。备份包含私人运行和可能存在的本地凭据，须存入受限位置。

Stop every process or container that can write the selected instance. The backup covers the configured data scope, including raw SQLite WAL and SHM files plus all Chroma state; a redacted Scenario snapshot is not an instance backup. POSIX refuses to proceed when open files cannot be verified, Windows retains exclusive handles, and volume backup rejects sources still mounted by running containers. The source SQLite is never recovery-written during backup. Copy and verify source consistency first, then inspect a temporary restored copy. Backups contain private runs and may contain local credentials, so they belong in restricted storage.

## 恢复、验证与回滚 / Restore, Verify, and Roll Back

恢复只写新目标目录或新卷，不清空、不覆盖已有实例。路径穿越、链接或 junction、重复/大小写冲突名称、意外成员和 checksum 不一致都必须拒绝。

能列出压缩包不等于恢复成功。`backup_and_restore_verified` 要求真正展开临时副本并核对文件 hash、SQLite 完整性、迁移版本、表计数及 Chroma SQL 标记；最终镜像门禁另外用 Chroma client 读取恢复的数据。不能把仅有标记检查说成完整应用读回。

升级前保留完整备份及旧 backend/frontend 的确切 digest。相同版本的恢复门禁不证明旧程序能读取新版本写入的数据；即使没有新数据库迁移，枚举和报告 payload 也可能不兼容。未证明向后兼容时，回滚用升级前备份在独立目标恢复，并匹配旧镜像对。

Restore writes only to a new target directory or volume and never clears or overwrites an existing instance. Path traversal, links or junctions, duplicate or case-colliding names, unexpected members, and checksum mismatches all fail closed. Listing an archive is not recovery. `backup_and_restore_verified` requires extracting a temporary copy and checking file hashes, SQLite integrity, migration version, table counts, and Chroma SQL markers; the final image gate separately reads restored data through the Chroma client. Marker checks alone are not complete application readback. Before upgrade, retain a complete backup and the exact old backend/frontend digests. A same-version restore gate does not prove an old program can read data written by the new version, even without a schema migration, because enums and report payloads may change. Unless backward compatibility is proven, rollback restores the pre-upgrade backup into an isolated target and pairs it with the old image digests.
